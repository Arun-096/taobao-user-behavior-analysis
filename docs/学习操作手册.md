# 从零自己做・操作手册（先读这个）

## 两个文件夹的分工（重要）



| 文件夹                             | 角色          | 你怎么用                     |
| ------------------------------- | ----------- | ------------------------ |
| `taobao-user-behavior-analysis` | **标准答案册**   | 平时不许偷看！自己写完一节，才打开对应文件对答案 |
| `taobao-practice`（本文件夹）         | **你自己的作业本** | 所有代码、SQL 都在这里从零写         |

你的目标不是 "跑通一遍"，而是**关掉答案能自己写出来**。跑通我写的代码不算你的，自己写出来的才算。

## 每道题 / 每个脚本的标准动作（四步循环）



1. **先自己写 20 分钟**：只看题目（my\_sql 里的练习题、my\_src 里的 TODO），不许翻答案。

   卡住先查知识点（见每题附的 "查什么"），而不是直接抄。

2. **再对答案**：打开标准答案册对应文件，逐行对比，把差异和思路记在题目注释里。

3. **关掉答案重写**：在你的文件里把刚才没写出来的部分重写一遍，能独立跑通 / 查对才算过。

4. **第二天默写**：开始新任务前，先把昨天卡住的题不看答案默写一遍（这是对抗 "一看就懂、一写就废" 的关键）。

> 时间盒：单条 SQL 最多卡 20 分钟就去对答案，别耗一晚上；但对完必须重写。

## 卡住时查什么（按这个顺序，别一卡就翻答案）



1. 报错信息：从最后一行往前读，先看懂它在抱怨什么

2. 官方文档 / 菜鸟教程 /w3schools 查具体函数用法（搜 "pandas dropna"、"sql row\_number"）

3. GitHub 同类项目搜写法（答案册 README 给了参考仓库）

4. 以上都不行，再打开标准答案对照 —— 并且在题目注释里写明"我卡在哪、答案怎么解决的"

* 能不看代码讲清清洗每一步 "删了什么、为什么"
